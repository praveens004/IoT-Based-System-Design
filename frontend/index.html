How this demo maps to SOA

Service consumers

The ESP32 (writes) and the user app (reads). Both know only the service's interface, never the table.

Service contract

REST: POST/GET /api/sensors. SOAP: the WSDL, which the client stubs are generated from. Open WSDL

Service provider

One sensor service with two front doors (SOAP and REST). It owns the business rules and the data access.

Data store

H2 database, shared by both front doors. Changing the schema never touches a device or the user app. Open H2 console
